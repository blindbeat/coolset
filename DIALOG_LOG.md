## 2026-04-29

- Added a Stop hook (`.claude/settings.json`) running `pnpm run check` before turn end so formatting/lint/types regressions block the agent.
- Stripped Vite default boilerplate down to a centered "hello world". Removed demo assets, `App.css`, and the custom CSS in `index.css`.
- Added `.oxfmtrc.json` enabling oxfmt's built-in Tailwind class sorting (reads theme from `src/index.css`, recognizes `clsx`/`cn`). Added `@tanstack/react-table`, `clsx`, and `tailwind-merge` dependencies.
- Built the grocery table from the Figma reference: a shadcn-style `<Table>` primitive driven by TanStack Table, read-only. Numeric columns are right-aligned via a `meta.numeric` flag on the column definition rather than scattered class checks, source rows are pre-flattened so column defs use plain string accessors, and numbers go through a module-scope `Intl.NumberFormat`.
- Switched typechecking from `tsc` to `tsgo`, the new Go-based TypeScript compiler from Microsoft. Pinned to the `beta` channel so it tracks upstream as it stabilizes. Confirmed it actually catches errors (not just exiting silently) and updated `CLAUDE.md`.
- Added pagination to the grocery table per the Figma reference, using Lucide for the chevrons. The component splits in two: a presentational `Pagination` that takes plain props (page index/size, totals, handlers) and a thin `TablePagination` wrapper that consumes a TanStack `Table` instance and forwards the right state — so the feature site is just `<TablePagination table={table} />`.
- Installed shadcn/ui with the Base UI flavor. The critical flag was `--base base` on `init` — missed on the first try, which silently produced a Radix-based preset and required a clean re-run. Added the shadcn `Button` component and used it for the pagination's prev/next chevrons; dropped the `asChild` prop and the `radix-ui` dep since nothing needs polymorphic rendering yet.
- Made the grocery table scroll inside its own box with a sticky header. The page is now capped at viewport height so the table is what overflows, not the page. Few rows hug their content (no empty space below), many rows shrink the table and scroll under the header. Pulled the scroll wrapper out into its own `TableContainer` so callers size it directly. Borders broke once the header went sticky — `border-collapse` paints lines on the table grid, not on the cells that move — so the table is now `border-separate` with the grid lines moved onto the cells themselves. They travel with the sticky header and stay 1px because each line is owned by only one side of any cell pair.
- Added a section filter to the grocery table, fed into TanStack via a controlled `columnFilters` array with `filterFn: "equalsString"` for exact match. The UI is the shadcn `Select` (Base UI flavor), with `null` representing "no filter" end-to-end — Base UI accepts any value type, so a `<SelectItem value={null}>` works without a sentinel string. The `columnFilters` array is wrapped in `useMemo` to keep its reference stable across renders; without that, TanStack's `autoResetPageIndex` saw a fresh array on every render and looped pagination resets infinitely.
- Made `TableHead` sort-aware. It accepts an optional TanStack `Header<TData, unknown>` and adapts in place: same `<th>` markup either way, with sorting logic the only thing that changes. When the column can sort, the th gets a click handler, `aria-sort`, hover styling, and an arrow slot showing `ArrowUpDown` muted while unsorted and `ArrowUp`/`ArrowDown` in slate-950 once active. When it can't, none of that renders — the arrow wrapper itself is gated by `getCanSort()` so the flex parent's `gap-2` collapses and labels sit flush left for non-sortable columns. The Section column opts out via `enableSorting: false`. `TableHead` doesn't know about content — the caller still passes `flexRender(...)` as children, matching the body cells.
- Wired left-column pinning into `TableHead` and `TableCell`. Both primitives read `column.getIsPinned()` and, when pinned left, apply `position: sticky` plus an inline `left: column.getStart('left')` offset and a `bg-white` so scrolled cells don't bleed through. Body cells get `z-1`; header cells get `z-20` so the corner stays above the existing `z-10` sticky thead during diagonal scroll. `TableCell` now takes an optional `cell?: Cell<TData, unknown>` prop so it can read the same pinning state from TanStack without the call site needing per-id checks. The grocery table hardcodes `columnPinning: { left: ['name'] }` in `initialState`. The sticky behavior only becomes visible once the table actually overflows its container horizontally — column-width strategy to make that overflow happen is a separate concern.
- Made the grocery-table header and pagination footer wrap cleanly when the page gets narrow. The wide-row layout is unchanged — title and section select still hug opposite edges, pagination groups stay far apart — but the rows now stack onto two lines with a tighter vertical gap when there isn't room. Also tidied a couple of React type imports that were pulling in the whole namespace just to reference one type.
- Replaced the click-on-th sort interaction with dedicated buttons inside `TableHead` so sorting and pinning are keyboard-reachable. The cell now lays out as three flex slots — sort button, column label, pin button — with each button rendered through the shadcn `Button` (ghost variant, `icon-xs` size) for native focus rings and consistent hover. The sort button only renders when `getCanSort()`; the pin button only when `getCanPin()`. Pin clicks call `table.setColumnPinning({ left: [...] })` directly, so the pin replaces any previously pinned column instead of accumulating — only one column is pinnable at a time. Pin state is communicated via `aria-pressed` with a constant `aria-label="Pin column"` (the canonical toggle-button pattern; mixing it with a state-changing label produced redundant SR output) and a `slate-950` icon when active. The pinned column gets a right-edge shadow as visual depth cue, defined as a Tailwind v4 theme token (`--shadow-pinned` in `index.css`, oklch black) so call sites reference `shadow-pinned` instead of arbitrary CSS. Default pinning was removed — first render has no pinned column; users opt in via the pin button.
- Swapped the native `<select>` rows-per-page control in `Pagination` for the shadcn `Select` (Base UI flavor) — same primitive already powering the section filter, so the two dropdowns now look and behave the same. Dropped the manual `ChevronDown` overlay and the wrapping `<label>` (the trigger carries its own `aria-label="Rows per page"` and the visible "Rows per page:" text sits beside it as a sibling span). Base UI's `onValueChange` types its argument as `number | null` to allow a cleared selection, which doesn't apply to a closed list of page sizes — guarded with `(v) => v !== null && onPageSizeChange(v)` rather than asserting non-null.
- Cleaned up repeated `text-slate-950` and `border-slate-200` in the table by leaning on the design tokens. The body already applies `text-foreground` (= `--color-zinc-950`), and the base layer's `* { @apply border-border ... }` already supplies `--border` (= `--color-zinc-200`) as the default border color, so cells and the title can drop the explicit classes entirely. The two override cases inside the th's muted `text-zinc-500` (active sort arrows, pinned-pin button) now reference `text-foreground` instead of a hard-coded slate, so they track the token. Briefly trialed flipping the foreground token to slate-950 before settling on zinc to keep the palette consistent with the rest of the surface. Also collapsed `grocery-table.tsx`'s `useState` + `useMemo` mirror of the section filter into direct calls to TanStack's column filter API — `getColumn('section').getFilterValue()` / `setFilterValue()` — since the table already owns that state and the local copy was just a render-loop hazard waiting to happen.
- Added auto column pinning that pins the name column on narrow viewports but lets manual clicks override forever. New hook `useIsViewportBelow(minWidth)` runs a `ResizeObserver` on `document.documentElement` and stores only the boolean, so React re-renders only when the threshold is actually crossed. The grocery table now drives `columnPinning` controlled with `manualPinning: ColumnPinningState | null` layered over an auto value derived from the hook: `effectivePinning = manualPinning ?? autoPinning`. Storing manual as the native TanStack shape (rather than a `boolean | null` translated at the edges) keeps `onColumnPinningChange` trivial — resolve the updater, set state, done.
